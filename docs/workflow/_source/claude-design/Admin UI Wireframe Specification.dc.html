CMS/MAM Workflow Admin UI Wireframe Specification

워크플로우 관리자 화면 와이어프레임 설계서 — 운영 콘솔 설계 기준

문서 버전 1.0 · 작성일 2026-07-04 · 상태: DRAFT · 선행 문서: Job Type Definition · DB Table Spec · Queue & Worker Spec · State Machine Spec (각 v1.0)

1. 문서 목적

본 문서는 워크플로우 관리자 화면의 정보 구조·화면별 구성·수동 조작 정책·API·권한을 정의한다. 이 화면은 단순 목록이 아니라 운영 콘솔이다 — 업로드된 미디어가 지금 어떤 처리 단계에 있는지, 어떤 Job이 왜 실패했는지, 어떤 Worker가 동작 중인지 즉시 파악하고, 재시도·취소·Lock 회수·Worker 비활성화 같은 조치를 안전하게(상태 기계 검증 + 감사 로그) 수행하는 것이 목적이다. UI는 Frame CMS 디자인 시스템을 사용한다.

3. 워크플로우 대시보드

  • 1행 — 경고 배너 (조건부): Worker OFFLINE/ERROR, 필수 실패, 큐 임계 초과 시 최상단 빨간/주황 배너. 없으면 미표시.
  • 2행 — 콘텐츠 카드 3장: 처리 중(PROCESSING) / READY / FAILED — FAILED > 0이면 카드 자체를 danger 스타일로.
  • 3행 — Job 상태 카드 6장: WAITING · READY · RUNNING · RETRY · FAILED · TIMEOUT (건수 + 전 시간 대비 증감).
  • 4행 — 좌: 처리량 그래프 (최근 24h, 시간당 SUCCESS 건수 막대 + 실패 건수 라인) / 우: Worker 요약 (ONLINE/BUSY/OFFLINE/ERROR 도넛 + 목록 상위 5).
  • 5행 — 운영 지표 스트립: TC Queue Length · 평균 처리 시간(p50/p95) · 실패율 · 재시도율 · 최근 1시간 처리량 — 임계 초과 값은 주황/빨강 강조.
  • 새로고침: 10초 자동 폴링 + 수동 버튼. 모든 카드는 클릭 시 필터된 목록으로 이동.

4. 콘텐츠 처리 현황 목록

컬럼: ID · 썸네일+제목 · 미디어 유형 · 콘텐츠 상태 뱃지 · 현재 단계(RUNNING 중 job_type) · 전체 진행률(완료 필수 job ÷ 전체 필수 job) · 실패 뱃지 · Proxy ✓ · Thumbnail ✓ · INDEX 상태 · PUBLISH 상태 · 업로드자 · 등록일 · 마지막 업데이트 · 액션(⋯ 메뉴).

필터: 콘텐츠 상태(멀티) · 미디어 유형 · 실패만 보기 토글 · 처리 기간(범위) · 업로드자 · 현재 Job 단계 · Worker 유형 · 검색어(제목/파일명/ID). 자주 쓰는 조합은 프리셋 저장.

액션: 상세 보기 · 실패 지점부터 재처리 · 전체 재처리 · PUBLISH 재시도 · 콘텐츠 취소 · 로그 보기 — 노출 조건은 §11 정책을 따른다.

5. 콘텐츠 처리 상세 화면

  • 상단 헤더: 썸네일 · 제목 · 콘텐츠 상태 뱃지 · media_type · 업로드자/등록일 · 주요 액션 버튼(재처리·취소·로그).
  • 좌측 컬럼: 원본 파일 정보(파일명·크기·checksum·detected_mime — 다운로드 링크 없음, 권한자용 별도 요청 버튼만) · Master rendition(경로 마스킹, zone 뱃지 🔒) · Proxy/Thumbnail/Catalog rendition 목록(미리보기 가능) · Search Index 상태.
  • 우측 메인: Workflow Instance 정보(템플릿·버전·시작/종료) → Job Pipeline Timeline → Job별 상태 목록(테이블) → 최근 로그 10건.
  • Pipeline Timeline: TM → VERIFY → MA → [TC | IMAGE_TC | AUDIO_TC | DOC_PREVIEW] → [CA | OCR | TEXT_EXTRACT] → INDEX → PUBLISH → CLEANUP 을 가로 스텝 UI로. 각 박스: job_type · 상태 뱃지 · 시작/종료 시각 · 소요 시간 · Worker 이름 · retry_count(>0이면 뱃지) · 진행률 바(RUNNING) · 실패 사유 1줄 · [로그] 버튼. SKIPPED는 점선 박스, 실패 전파 SKIPPED는 점선+빨간 테두리.
  • 실패 사유 패널: 실패 job이 있으면 타임라인 아래 danger 카드로 fail_reason_code + 사용자용 설명 + 조치 제안(예: "손상 파일 — 재업로드 필요").

6. Job 큐 현황 화면

컬럼: job_id · content(썸네일+ID) · job_type · priority(편집 가능) · status(READY/RETRY) · next_attempt_at · retry_count/max_retry · created_at · 대기 시간(강조: > 10분 주황) · 예상 Worker 유형 · 액션.

필터: job_type · status · priority 범위 · retry_count ≥ N · next_attempt_at 도래 여부 · 대기 시간 ≥ N분 · content_id.

액션: 우선순위 변경(인라인 셀렉트) · 수동 실행 예약(next_attempt_at=now) · 취소 · 상세 보기. 상단에 job_type별 대기 건수 미니 카드.

7. RUNNING Job 화면

컬럼: job_id · content · job_type · Worker(링크) · 진행률 바(%+message) · 남은 예상 시간 · started_at · 경과 시간 · timeout_sec · 타임아웃 임박(경과 > 80% 주황 / > 95% 빨강 점멸) · locked_until · heartbeat_at(지연 시 경고) · 액션.

장시간 작업 진행률: TC는 ffmpeg out_time 기반 %를 진행률 바 + "00:12:30 / 00:41:00" 형태의 시간 병기로, DOC_PREVIEW/OCR은 "37 / 120 페이지"로 표시 — 운영자가 '멈춘 것인지 느린 것인지'를 판별할 수 있게 진행률 마지막 갱신 시각을 함께 표시하고 2분 이상 미갱신이면 stall 경고 아이콘.

액션: 로그 보기 · Job 취소 요청 · Lock 강제 회수 · Worker 상세 보기.

8. 실패 Job 화면

컬럼: 선택 체크박스 · job_id · content · job_type · is_required(영향도 뱃지) · fail_reason_code · 실패 메시지(1줄, 전체는 툴팁) · retry_count/max_retry · 마지막 Worker · failed_at · 액션.

영향도 표시: 필수 실패 — "콘텐츠 FAILED · PUBLISH 차단" 빨간 뱃지 / 선택 실패 — "READY 가능 · 경고" 주황 뱃지. 기본 정렬은 필수 실패 우선.

액션: 단건 재시도 · 선택 일괄 재시도(같은 fail_reason끼리 권장 경고) · 실패 사유 보기(모달: code·메시지·마지막 stderr 발췌) · 로그 보기 · 콘텐츠 상세 · 후속 SKIPPED 목록 보기(어떤 job이 전파로 생략됐는지).

9. Worker 상태 대시보드

컬럼: worker_id · worker_name · worker_type · 상태 뱃지 · supported_job_types(칩) · hostname · ip · last_heartbeat_at · heartbeat delay(30초↑ 주황, 90초↑ 빨강) · current_job(링크) · max_concurrency(사용/전체) · GPU ✓ · cpu/mem · version · 액션.

액션: 비활성화(drain) · 재활성화 · ERROR 해제 · 현재 Job 보기 · Worker 로그 보기.

Worker 상태뱃지 색의미

BUSY파랑 (accent)실행 중 — 정상
OFFLINE빨강 (danger) + 행 강조heartbeat 유실 — 즉시 확인

10. Job 로그 상세 화면

  • 상단: Job 기본 정보 카드 — job_id·type·상태·content 링크·worker·retry_count·payload 요약.
  • 좌측 — 상태 전이 타임라인 (histories): 세로 타임라인. 각 노드 = from→to 뱃지 · actor · note · 시각 · 구간 소요. "무슨 일이 있었나"를 답한다.
  • 우측 — 실행 로그 (logs): attempt 탭(1차/2차/…) → command(복사 버튼) · stdout/stderr(접이식, 모노스페이스, 검색) · message · detail JSON(트리 뷰). "왜 그랬나"를 답한다.
  • 하단: 생성된 rendition 목록(type·zone·크기·미리보기) · 실패 사유 카드 · 관리자 조작 이력(histories 중 actor=admin 필터 뷰).
  • history와 log의 구분은 화면에서 "타임라인(상태)" / "실행 로그(상세)" 두 패널 제목으로 명시하고, 타임라인 노드 클릭 시 해당 시각의 로그로 스크롤 동기화.

workflow.logs.view로그 상세 열람 (경로 등 내부 정보 포함)LOW
workflow.retry재시도·우선순위 변경LOW
workflow.canceljob·콘텐츠 취소MED
workflow.reprocess콘텐츠 재처리MED
workflow.release_lockLock 강제 회수HIGH
workflow.worker.manageWorker 비활성화·ERROR 해제HIGH
workflow.force_publishPUBLISH 강제 (비상용 — 기본 미부여)HIGH
content.master.download원본 다운로드 (워크플로우 권한과 별개, 감사 로그 필수)HIGH

조회(view)와 조작 권한을 분리하고, HIGH 권한은 역할(Role)에 기본 포함하지 않는다 — 개별 부여 + 부여 이력 관리.

17. 사용자 경험 기준

  • 실패 원인 즉시 노출 — 실패 뱃지에서 1클릭 이내에 fail_reason + 사람이 읽을 설명 + 조치 제안이 보인다. 목록에서도 사유 1줄 표시.
  • 필수/선택 실패 구분 — 색·뱃지·기본 정렬로 항상 구분. 선택 실패가 필수 실패처럼 보이면 안 된다.
  • 조작 안전장치 — 위험도에 따라 확인 모달·사유 입력·확인 문구 타이핑(§11). 버튼은 상태 기계상 가능한 경우에만 노출.
  • RUNNING 감시성 — 진행률 + 마지막 갱신 시각 + 타임아웃 임박 표시로 "느림 vs 멈춤"을 구분 가능하게.
  • Worker OFFLINE 즉시 인지 — 전 화면 공통 상단 배너 + 대시보드 카드 강조.
  • Master 보호 — 화면 어디에도 원본 직접 링크를 노출하지 않는다. 경로는 마스킹, 다운로드는 content.master.download 권한 + 사유 입력 + 감사 로그를 거치는 별도 요청 플로우.
  • 모든 조작에 사유 — MED 이상 액션은 사유 입력 필수, 조작 이력은 콘텐츠·job 상세에서 열람 가능.
  • 시각·시간대는 서버 UTC 저장, 화면은 운영자 로컬 표기(툴팁에 UTC 병기).

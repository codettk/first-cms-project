CMS/MAM Workflow DB Table Specification

워크플로우 DB 테이블 명세서 — Laravel + PostgreSQL 구현 기준

문서 버전 1.0 · 작성일 2026-07-04 · 상태: DRAFT · 선행 문서: Workflow Job Type Definition v1.0

1. 문서 목적

본 문서는 작업 유형 정의서(v1.0)에서 정의한 13개 워크플로우 작업을 실제로 저장·실행·추적하기 위한 PostgreSQL 테이블 설계를 정의한다. Laravel(Eloquent + Migration) 기반 구현을 전제로 하며, 첨부된 DDL은 설계 검토용 초안이다 — 최종 확정 전 성능 테스트와 파티셔닝 검토를 거친다.

설계 원칙: ① 콘텐츠 상태와 작업 상태의 분리 ② 상태 전이의 상태 기계 검증 ③ 이력(append-only)과 로그의 분리 ④ 원본(MASTER)과 파생 파일(rendition)의 분리 ⑤ 중복 실행을 막는 잠금(lease) 기반 동시성 제어.

2. 전체 ERD 개념

  • contents 1 — N media_files 1 — N media_renditions : 콘텐츠 → 논리 파일 → 물리 파생 파일 계층.
  • workflow_templates 1 — N workflow_template_steps : 미디어 유형별 워크플로우 정의(설계도).
  • contents 1 — N workflow_instances 1 — N workflow_jobs : 콘텐츠에 대해 템플릿을 인스턴스화한 실행 단위.
  • workflow_jobs N — N (self) via workflow_job_dependencies : 선행/후행 DAG.
  • workflow_jobs 1 — N workflow_job_histories(상태 전이), 1 — N workflow_job_logs(실행 로그).
  • workflow_worker_agents 1 — N workflow_job_locks : Worker의 job lease.
  • contents 1 — 1 search_index_states : 검색엔진 색인 동기화 상태.

4. 테이블별 상세 명세

4.1 contents

목적콘텐츠 마스터 레코드. 콘텐츠 전체 상태(라이프사이클)를 관리하며 workflow job 상태와 분리한다.
사용 시나리오업로드 시 생성(UPLOADING) → 등록(REGISTERED) → 워크플로우 시작(PROCESSING) → PUBLISH 성공(READY). 목록/상세 API의 루트 엔터티.
컬럼타입NULL기본값 / 제약설명
idbigintNPK, identity콘텐츠 ID
uuiduuidNUQ, gen_random_uuid()외부 노출용 ID (API·URL은 uuid만 사용)
titlevarchar(500)N—콘텐츠 제목
descriptiontextY—설명
media_typevarchar(10)YCHECK: VIDEO/IMAGE/AUDIO/DOCMA 확정 전 NULL, 확정 후 갱신
statusvarchar(20)N'UPLOADING', CHECK(§5)콘텐츠 상태
workflow_versionvarchar(20)Y—인스턴스 생성 시점의 템플릿 버전 스냅샷
published_attimestamptzY—READY 전환 시각
created_bybigintNFK → users.id업로더
created_at / updated_attimestamptzNnow()Laravel timestamps
deleted_attimestamptzY—soft delete (DELETED 상태와 병행)

인덱스: (status, created_at DESC) — 상태별 목록 조회. (media_type, status) — 유형별 대시보드. uuid UNIQUE.
예시: id=1001, uuid=…, title='video_001', media_type='VIDEO', status='READY'
운영 주의: 상태 변경은 반드시 상태 기계 검증(§6)을 거친 트랜잭션으로. DELETED 콘텐츠에는 신규 job 생성을 금지(애플리케이션 가드 + 트리거).

4.2 media_files

목적업로드된 논리 파일 단위 관리. 원본 파일의 식별·무결성 정보를 보관한다.
사용 시나리오업로드 완료 시 생성. TM이 master_path 확정, VERIFY가 checksum 대조. 콘텐츠 1건에 다중 파일(멀티파트 자산) 허용.
컬럼타입NULL기본값 / 제약설명
idbigintNPK, identity파일 ID
content_idbigintNFK → contents.id소속 콘텐츠
original_filenamevarchar(500)N—업로드 원본 파일명
extvarchar(20)N—확장자(소문자)
detected_mimevarchar(100)Y—VERIFY가 판정한 실제 MIME
file_sizebigintNCHECK > 0바이트
checksumvarchar(64)N—SHA-256 (업로드 시 계산)
temp_pathvarchar(1000)Y—Temp Storage 경로 (CLEANUP 후 NULL)
media_infojsonbY—MA 추출 결과 전체(JSON)
created_at / updated_attimestamptzNnow()—

인덱스: content_id. checksum — 중복 업로드 탐지 조회.
예시: id=5001, content_id=1001, original_filename='video_001.mov', file_size=8123456789, checksum='ab3f…'
운영 주의: media_info는 raw 추출값 저장 — 조회 빈도 높은 값(길이·해상도)은 renditions/검색 색인에 중복 보관.

4.3 media_renditions

목적원본(MASTER)과 모든 파생 파일(물리 파일)을 단일 모델로 관리. 웹 표출은 이 테이블의 비-MASTER rendition만 참조한다.
사용 시나리오TM이 MASTER 생성, TC/IMAGE_TC/AUDIO_TC/CA/DOC_PREVIEW가 각 rendition 생성. 상세 API는 content_id + rendition_type으로 조회.
컬럼타입NULL기본값 / 제약설명
idbigintNPK, identity—

media_file_idbigintNFK → media_files.id파생 원천 파일
rendition_typevarchar(30)NCHECK(§8 목록)MASTER / PROXY_VIDEO / … / EXTRACTED_TEXT
storage_zonevarchar(30)NCHECK: TEMP/MASTER/PROXY/THUMBNAIL/CATALOG/DOCUMENT/ARCHIVE저장소 구역 — MASTER zone은 웹 접근 금지
variant_keyvarchar(50)N'default'동일 rendition_type 내 변형 구분 (720p, thumb_480…) — 다중 화질 확장 키
pathvarchar(1000)NUQ (storage_zone, path)스토리지 내 경로
file_sizebigintY—바이트
checksumvarchar(64)Y—SHA-256
mime_typevarchar(100)Y——
width / heightintY—영상·이미지
duration_msbigintY—영상·오디오 길이

created_attimestamptzNnow()—

인덱스: (content_id, rendition_type) — 상세 화면 핵심 조회. (storage_zone, path) UNIQUE — 경로 중복 방지. checksum.
예시: content_id=1001, rendition_type='PROXY_VIDEO', storage_zone='PROXY', path='proxy/2026/07/1001_720p.mp4', width=1280, height=720, duration_ms=734000
운영 주의: 재실행(멱등) 시 같은 (content_id, rendition_type, variant_key, page_no/timecode) 행은 upsert (unique 상세는 Migration Spec §7). MASTER 행 삭제는 콘텐츠 완전 삭제 배치에서만 허용.

4.4 workflow_templates

목적미디어 유형별 워크플로우 정의(설계도). 버전 관리로 정의 변경 시 기존 인스턴스에 영향 없음.
사용 시나리오MA의 media_type 확정 → 활성 템플릿 선택 → 인스턴스 생성. 예: VIDEO_INGEST v3.
컬럼타입NULL기본값 / 제약설명

namevarchar(200)N—표시명
media_typevarchar(10)NCHECK대상 유형
versionintN1템플릿 버전
is_activebooleanNtrue유형당 활성 1건 (partial UQ)
created_attimestamptzNnow()—

인덱스: partial UNIQUE (media_type) WHERE is_active — 유형당 활성 템플릿 1건 보장.
운영 주의: 템플릿은 수정하지 않고 새 버전 추가 후 활성 전환 — 실행 중 인스턴스와의 불일치 방지.

4.5 workflow_template_steps

목적템플릿을 구성하는 작업 단계와 기본 정책(필수 여부·재시도·타임아웃·의존)을 정의.

4.7 workflow_jobs

목적실제 실행되는 작업 단위. Worker가 소비하는 큐의 원본 데이터이자 상태 기계의 주체.
사용 시나리오인스턴스 생성 시 일괄 생성(WAITING) → 선행 SUCCESS 시 READY → Worker lease 후 RUNNING → SUCCESS/FAILED/….

운영 주의: 상태 변경은 반드시 이력 기록과 같은 트랜잭션. 대량 누적 시 월 단위 파티셔닝 검토(완료 job 아카이브).

4.8 workflow_job_dependencies

목적작업 간 선행 관계(DAG) 저장. Worker 스케줄러가 READY 전환 판정에 사용.
컬럼타입NULL기본값 / 제약설명
job_idbigintNFK → workflow_jobs.id, PK(복합)후행 작업

인덱스: PK (job_id, depends_on_job_id) + 역방향 (depends_on_job_id) — 선행 완료 시 후행 탐색.
READY 전환 쿼리: 선행 job이 모두 SUCCESS(또는 SKIPPED)인 WAITING job을 READY로 갱신.
운영 주의: 인스턴스화 시 사이클 검증(DAG 보장)을 애플리케이션에서 수행.

인덱스: locked_until — 만료 lease 회수 스캔.
운영 주의: PK가 job_id이므로 중복 lease는 DB 레벨에서 원천 차단. 만료 회수 시 job을 RETRY로 전환하고 이력 기록.

4.13 search_index_states

4.14 transcode_profiles (추가 제안)

TC/IMAGE_TC/AUDIO_TC의 출력 프리셋(코덱·해상도·비트레이트·포맷)을 코드가 아닌 데이터로 관리: id, code(UQ), media_type, output_format, params(jsonb), is_active. rendition·job payload가 profile_id로 참조하여 재현 가능성을 보장한다.

7. 작업 의존 관계 저장 방식

템플릿 단계의 depends_on(jsonb)을 인스턴스화 시점에 workflow_job_dependencies의 실제 job_id 쌍으로 풀어서 저장한다. 스케줄러는 아래 쿼리로 READY 전환 대상을 찾는다:

UPDATE workflow_jobs j SET status = 'READY', updated_at = now()
WHERE j.status = 'WAITING'
  AND NOT EXISTS (
    SELECT 1 FROM workflow_job_dependencies d
    JOIN workflow_jobs p ON p.id = d.depends_on_job_id
    WHERE d.job_id = j.id AND p.status NOT IN ('SUCCESS','SKIPPED')
  );

8. 파일·파생 파일 저장 방식

media_files(논리 파일) — media_renditions(물리 파일) 분리. rendition_type 허용값:

MASTER · PROXY_VIDEO · PROXY_IMAGE · PROXY_AUDIO · THUMBNAIL · CATALOG · PAGE_PREVIEW · DOCUMENT_PREVIEW · WAVEFORM · OCR_TEXT · EXTRACTED_TEXT

  • 웹 API는 storage_zone != 'MASTER'인 rendition만 서빙한다 — 쿼리 레벨 가드 + 스토리지 네트워크 분리 이중 방어.
  • MASTER 다운로드는 권한 검사 후 서명된 임시 URL 발급 방식으로만 제공.
  • CATALOG는 timecode_ms, PAGE_PREVIEW는 page_no로 다건 관리.
  • OCR_TEXT/EXTRACTED_TEXT는 파일 대신 텍스트 산출물 — path에 텍스트 파일 경로 또는 detail 참조 저장.
  • 장기 검토(P3): 텍스트 산출물은 추후 media_texts 테이블 분리 검토 — 후보 컬럼: id · content_id · media_file_id · rendition_id? · text_type(OCR|EXTRACTED|STT) · page_no? · timecode_ms? · text · confidence? · lang? · metadata jsonb · created_at. 현행 파일 경로 저장 방식은 유지.

9. Worker Agent 및 Lock 설계

소비(claim) 흐름 — PostgreSQL 기준, lease + SKIP LOCKED 병행:

BEGIN;
SELECT id FROM workflow_jobs
WHERE status IN ('READY','RETRY')
  AND (next_attempt_at IS NULL OR next_attempt_at <= now())
  AND job_type = ANY($supported)
ORDER BY created_at
LIMIT 1
FOR UPDATE SKIP LOCKED;

INSERT INTO workflow_job_locks (job_id, locked_by_worker_id, locked_until)
VALUES ($job_id, $worker_id, now() + interval '10 minutes');

UPDATE workflow_jobs SET status='RUNNING', worker_id=$worker_id,
  started_at=now(), retry_count=retry_count+... WHERE id=$job_id AND status IN ('READY','RETRY');
COMMIT;
  • FOR UPDATE SKIP LOCKED — 동시 claim 경합 제거. workflow_job_locks PK — 중복 lease DB 차단.
  • Worker는 실행 중 heartbeat마다 locked_until을 연장. 연장 실패(네트워크 단절) 시 자체 중단.
  • 스케줄러 배치가 locked_until < now()인 lock을 회수 → job을 RETRY(또는 TIMEOUT)로 전환 + 이력 기록.
  • Worker OFFLINE 판정: last_heartbeat_at이 3주기 이상 미갱신.

10. 인덱스 설계

인덱스사유
jobs (status, next_attempt_at) WHERE status IN ('READY','RETRY')큐 소비 핵심 경로 — partial index로 크기 최소화, 상시 고빈도

12. 운영 시 고려사항

  • 파티셔닝: workflow_job_histories·workflow_job_logs는 월 단위 range 파티셔닝 + 보존 정책(이력 12개월, 로그 90일).
  • 아카이브: 종결(SUCCESS/FAILED) 후 90일 지난 job은 아카이브 테이블로 이동해 큐 인덱스를 작게 유지.
  • 모니터링 지표: READY 큐 길이, RUNNING 평균 시간, 실패율, lease 회수 건수 — 대시보드 필수.
  • 백업: contents / media_renditions는 PITR 대상. Master Storage와 DB의 정합성 점검 배치(주 1회 checksum 대조).
  • Laravel 구현: 상태 전이는 단일 서비스 경유, 마이그레이션에 CHECK 제약 포함, jsonb 컬럼은 casts로 매핑.

13. DDL 초안 (설계 검토용 — 발췌)

CREATE TABLE contents (
  id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  uuid          uuid NOT NULL DEFAULT gen_random_uuid() UNIQUE,
  title         varchar(500) NOT NULL,
  description   text,
  media_type    varchar(10) CHECK (media_type IN ('VIDEO','IMAGE','AUDIO','DOC')),
  status        varchar(20) NOT NULL DEFAULT 'UPLOADING'
                CHECK (status IN ('UPLOADING','REGISTERED','PROCESSING','READY','FAILED','ARCHIVED','DELETED')),
  workflow_version varchar(20),
  published_at  timestamptz,
  created_by    bigint NOT NULL,
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now(),
  deleted_at    timestamptz
);
CREATE INDEX idx_contents_status ON contents (status, created_at DESC);

CREATE TABLE workflow_jobs (
  id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  instance_id   bigint NOT NULL REFERENCES workflow_instances(id),
  content_id    bigint NOT NULL REFERENCES contents(id),
  job_type      varchar(30) NOT NULL,
  status        varchar(20) NOT NULL DEFAULT 'WAITING'
                CHECK (status IN ('WAITING','READY','RUNNING','SUCCESS','FAILED','RETRY','SKIPPED','CANCELED','TIMEOUT')),
  is_required   boolean NOT NULL DEFAULT true,
  priority      smallint NOT NULL DEFAULT 100 CHECK (priority BETWEEN 0 AND 1000),
  cancel_requested_at timestamptz,
  retry_count   int NOT NULL DEFAULT 0,
  max_retry     int NOT NULL DEFAULT 3,
  timeout_sec   int NOT NULL DEFAULT 600,
  next_attempt_at timestamptz,
  payload       jsonb,
  result        jsonb,
  fail_reason_code varchar(50),
  worker_id     bigint,
  started_at    timestamptz,
  finished_at   timestamptz,
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now(),
  UNIQUE (instance_id, job_type)
);
CREATE INDEX idx_jobs_queue ON workflow_jobs (status, next_attempt_at)
  WHERE status IN ('READY','RETRY');
CREATE INDEX idx_jobs_running ON workflow_jobs (started_at) WHERE status = 'RUNNING';
CREATE INDEX idx_jobs_content ON workflow_jobs (content_id);
CREATE INDEX idx_jobs_failed ON workflow_jobs (finished_at DESC) WHERE status = 'FAILED';

CREATE TABLE workflow_job_dependencies (
  job_id            bigint NOT NULL REFERENCES workflow_jobs(id),
  depends_on_job_id bigint NOT NULL REFERENCES workflow_jobs(id),
  PRIMARY KEY (job_id, depends_on_job_id),
  CHECK (job_id <> depends_on_job_id)
);
CREATE INDEX idx_dep_reverse ON workflow_job_dependencies (depends_on_job_id);

CREATE TABLE media_renditions (
  id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  content_id    bigint NOT NULL REFERENCES contents(id),
  media_file_id bigint NOT NULL REFERENCES media_files(id),
  rendition_type varchar(30) NOT NULL CHECK (rendition_type IN
    ('MASTER','PROXY_VIDEO','PROXY_IMAGE','PROXY_AUDIO','THUMBNAIL','CATALOG',
     'PAGE_PREVIEW','DOCUMENT_PREVIEW','WAVEFORM','OCR_TEXT','EXTRACTED_TEXT')),
  storage_zone  varchar(30) NOT NULL CHECK (storage_zone IN
    ('TEMP','MASTER','PROXY','THUMBNAIL','CATALOG','DOCUMENT','ARCHIVE')),
  variant_key   varchar(50) NOT NULL DEFAULT 'default',
  path          varchar(1000) NOT NULL,
  file_size     bigint,
  checksum      varchar(64),
  mime_type     varchar(100),
  width int, height int,
  duration_ms   bigint,
  page_no       int,
  timecode_ms   bigint,
  profile_id    bigint,
  created_at    timestamptz NOT NULL DEFAULT now(),
  UNIQUE (storage_zone, path)
);
CREATE INDEX idx_rend_lookup ON media_renditions (content_id, rendition_type);

CREATE TABLE workflow_job_locks (
  job_id              bigint PRIMARY KEY REFERENCES workflow_jobs(id),
  locked_by_worker_id bigint NOT NULL REFERENCES workflow_worker_agents(id),
  locked_at           timestamptz NOT NULL DEFAULT now(),
  locked_until        timestamptz NOT NULL,
  heartbeat_at        timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_locks_expiry ON workflow_job_locks (locked_until);

전체 DDL은 마이그레이션 작성 시 본 명세 §4를 기준으로 전개한다.

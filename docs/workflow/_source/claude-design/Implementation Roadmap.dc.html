Frame CMS/MAM Workflow Implementation Roadmap

워크플로우 구현 로드맵 — 설계 문서 v1.1 세트 기반 구현 실행 계획

문서 버전 1.0 · 작성일 2026-07-04 · 연관: WBS & Milestone Plan · MVP Scope & Git Strategy

1. 전체 구현 전략

  • 기반 → 엔진 → 파이프라인 → 운영 도구 순서 — 하위 계층(DB·상태 기계)이 검증되기 전에 상위 계층을 올리지 않는다.
  • MVP 우선: VIDEO 최소 파이프라인(UPLOAD → TM → VERIFY → MA → TC → CA → INDEX → PUBLISH → CLEANUP)을 end-to-end로 먼저 완성하고, IMAGE/AUDIO/DOC·확장 기능은 그 뒤에 얹는다.
  • 계약 고정: 설계 문서 v1.1(수정 지시서 반영 완료)이 단일 기준 — 구현 중 설계 변경은 문서 수정 → 코드 순서로만.
  • 각 단계는 완료 기준(DoD) 충족 + 테스트 통과 후에만 다음 단계로 진행.
  • 번호 체계 기준: 본 Roadmap의 Phase는 기존 12단계 구현 순서표를 실행 관점에서 재그룹화한 것이다. 세부 작업 기준은 WBS를 우선하고, 전체 흐름과 의존성 기준은 Roadmap을 우선한다.

2. 단계별 로드맵

Phase 0 — 문서 확정 [MVP]

항목내용
목적설계 문서 v1.1을 구현 기준으로 동결
주요 작업수정 지시서 반영 확인(완료) · OpenAPI 골격 → openapi.yaml 실파일 생성 · 팀 리뷰
선행 조건없음
완료 기준전 문서 v1.1 태깅 · openapi.yaml spectral lint 통과 · 팀 승인
산출물동결된 문서 세트 · openapi.yaml
위험 요소구현 중 설계 재변경 — 변경은 문서 선행 원칙으로 통제

Phase 1 — DB / Migration / Seed + Model [MVP]

항목내용
목적17개 테이블·제약·인덱스·trigger·seed를 코드화 — 시스템의 단일 진실 원천 구축
주요 작업enums → migrations(§순서 18단계) → CHECK/partial index/trigger → allowed_transitions·template·profile seed → Model/cast/relation/factory
선행 조건Phase 0
완료 기준migrate:fresh + seed 무오류 · Migration Spec §15 테스트 11항목 통과(전이 trigger·DELETED 가드·append-only 포함)
산출물migrations · seeders · Models · factories · 스키마 테스트
위험 요소trigger/enum/seed 3곳 전이표 불일치 — 일치 테스트를 CI에 먼저 넣는다

Phase 2 — StateMachine + Workflow 생성 [MVP]

항목내용
목적모든 상태 변경의 유일한 관문 확립 + 템플릿 기반 인스턴스/job/dependency 생성
주요 작업AbstractStateMachine + 5종 구현(CAS·history, 내부 트랜잭션 없음) · TransitionRunner · WorkflowInstanceFactory(템플릿 → jobs+dependencies, DAG 사이클 검증)
선행 조건Phase 1
완료 기준허용/금지 전이 전수 테스트 · CAS 충돌 시나리오 테스트 · VIDEO 템플릿 인스턴스화 시 8개 job·의존 생성 검증
산출물StateMachine 5종 · 인스턴스 생성 서비스 · 전이 테스트
위험 요소상태 변경 우회 코드 유입 — arch 테스트($fillable 제외·직접 update 금지)로 차단

Phase 3 — Scheduler + Worker 기반 [MVP]

항목내용
목적큐 오케스트레이션(READY 전환·타임아웃·Lock 회수)과 Worker 공통 루프(Claim·heartbeat·fencing) 완성
주요 작업Scheduler 데몬 7단계 틱(advisory lock) · JobClaimService(SKIP LOCKED) · JobLockService(lease·연장·회수) · AbstractWorker 루프 · WorkerAgentService · graceful shutdown
선행 조건Phase 2
완료 기준동시 Claim 이중 실행 0건 · lease 만료 자동 회수 → RETRY · fencing으로 늦은 결과 폐기 · SIGTERM drain 테스트 통과
산출물workflow:scheduler / workflow:worker 커맨드 · supervisor 설정 · 동시성 테스트
위험 요소동시성 버그는 재현 어려움 — N-Worker 통합 테스트를 이 단계에서 확보(뒤로 미루지 않음)

Phase 4 — Storage / Rendition / Profile [MVP]

항목내용
목적산출물 저장 계층 — zone 경로 해석·atomic rename·MASTER 보호·rendition upsert·프로파일 컴파일
주요 작업MediaStorageService(.tmp → rename, assertNotMasterMutation) · RenditionService(variant_key 포함 upsert) · ProfileCompiler(params → 도구 인자)
선행 조건Phase 1 (Phase 3과 병행 가능)
완료 기준upsert 3종 키 테스트 · MASTER 변조 시도 차단 테스트 · 비활성 프로파일 거부
산출물Storage/Rendition/Profile 서비스 + 테스트
위험 요소스토리지 마운트 구성이 늦어지면 통합 테스트 지연 — DevOps 선행 협의

Phase 5 — Job Handler [MVP: TM·VERIFY·MA·TC·CA·INDEX·PUBLISH·CLEANUP]

항목내용
목적VIDEO 파이프라인 end-to-end 완성
주요 작업1차: TM·VERIFY·MA·PUBLISH·CLEANUP(외부 도구 少) → 2차: TC(ffmpeg+진행률)·CA·INDEX → 3차(M6): IMAGE_TC·AUDIO_TC·DOC_PREVIEW·TEXT_EXTRACT·OCR
선행 조건Phase 3 + 4
완료 기준영상 1건 업로드 → READY 자동 전환(MVP 성공 시나리오) · 실패 유형별 RETRY/FAILED 분기 테스트 · TC 진행률 표시
산출물Handler 8종 · FailReasonCatalog · 파이프라인 통합 테스트
위험 요소ffmpeg 환경 편차 — 도구 버전 고정 이미지 선행 준비(폐쇄망). INDEX 일정 리스크: INDEX는 MVP 필수 job으로 유지(INDEX 성공 후 PUBLISH 진행)하되, 검색엔진 연동·폐쇄망 검증 지연 가능성이 있으므로 M3 게이트 전에 연결·mapping·upsert·조회 검증을 선행 확인한다. Mock INDEX는 개발 환경 테스트용으로만 허용 — 운영 MVP 게이트는 실제 INDEX 성공 기준

Phase 6 — Admin API [MVP: 조회 + 재시도·감사]

항목내용

주요 작업Query API(dashboard·contents·jobs·workers) → Command API(retry·cancel·release-lock·worker 관리) + AuditLogger + AvailableActionService · audit.context/write 미들웨어
선행 조건Phase 2 (조회는 Phase 5와 병행 가능)

산출물Controller·Service·Resource·FormRequest · 계약 테스트

Phase 7 — Admin UI [MVP: 대시보드·목록·상세·재시도]

주요 작업대시보드 → 콘텐츠 목록/상세(파이프라인 타임라인) → 실패 Job/재시도 → Worker 상태 → (M6) 큐 현황·로그 상세 고도화

산출물Admin UI 화면 · E2E 시나리오 테스트
위험 요소프론트가 자체 상태 판정 로직을 넣는 것 — 계약(actions 배열)만 사용

Phase 8 — 테스트 / 운영 준비 [MVP]

항목내용

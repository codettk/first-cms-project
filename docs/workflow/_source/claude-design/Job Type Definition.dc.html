CMS/MAM Workflow Job Type Definition

작업 유형 정의서 — DB 테이블 · Queue Job · Worker Agent · 관리자 화면 설계 기준 문서

문서 버전 1.0 · 작성일 2026-07-04 · 상태: DRAFT

1. 문서 목적

본 문서는 Frame CMS/MAM의 미디어 처리 워크플로우를 구성하는 13개 작업(Job) 유형의 입력·출력·실행 조건·성공/실패 판정·재시도 정책을 구현 가능한 수준으로 정의한다. 백엔드 개발자가 job 테이블, 메시지 큐, Worker Agent, 관리자 모니터링 화면을 설계할 때 본 문서를 단일 기준(Single Source of Truth)으로 사용한다.

핵심 원칙: 원본 Master 파일은 보관용이며, 웹 표출은 Proxy Media · Thumbnail · Catalog Image · Document Preview만 사용한다. 모든 작업은 이 분리 구조를 전제로 정의된다.

워크플로우 계층: Workflow Template(유형별 정의) → Workflow Template Step(단계 정의) → Workflow Instance(콘텐츠별 실행) → Workflow Job(실행 단위) → Workflow Job History(상태 전이 이력) / Workflow Job Log(실행 로그 — command·stdout·stderr·detail). 이력과 로그는 별도 테이블로 분리한다.

파일 계층: media_files는 업로드된 원본 파일 단위, media_renditions는 Worker가 생성한 Master·Proxy·Thumbnail·Catalog·Preview 산출물 단위로 역할을 분리한다.

3. 작업 유형별 상세 정의

3.1 TM / 파일 이동·복사

작업 코드TM
작업 목적Upload Temp Storage의 원본 파일을 Master Storage로 이동 또는 복사하고 원본 경로를 확정한다.
입력 데이터content_id, temp 파일 경로, 원본 파일명, 업로드 시 계산된 checksum(SHA-256)
출력 데이터Master Storage 경로(master_path), 이동 후 파일 크기, 이동 후 checksum
선행 작업콘텐츠 등록 완료 (콘텐츠 상태 = REGISTERED)
실행 조건temp 파일 존재, Master Storage 쓰기 가능, 스토리지 여유 공간 ≥ 파일 크기 × 1.1
성공 조건목적지 파일 존재 AND 파일 크기 일치 AND checksum 일치
실패 조건temp 파일 누락, 스토리지 용량 부족, I/O 오류, checksum 불일치
재시도 가능 여부가능 (멱등 — 재실행 시 기존 목적지 파일 덮어쓰기)
재시도 정책최대 3회, 지수 백오프(1분 → 5분 → 15분)
생성 파일/데이터Master Storage 내 원본 파일 1건
DB 저장 주요 값master_path, file_size, checksum, original_filename, moved_at
로그 기록 주요 값원본/목적지 경로, 파일 크기, checksum 전후 값, 소요 시간, 오류 코드
관리자 화면 표시작업 상태, 파일명, 파일 크기, 진행률(대용량 복사 시), 실패 사유
비고이동/복사 모드는 시스템 설정으로 결정. 복사 모드일 경우 temp 파일은 CLEANUP에서 삭제.

3.2 VERIFY / 파일 검증

작업 코드VERIFY
작업 목적Master Storage에 저장된 원본의 무결성과 처리 가능 여부를 판정한다. 실패 시 이후 모든 작업을 차단한다.
입력 데이터content_id, master_path, 등록 시 checksum, 허용 확장자/최대 용량 정책
출력 데이터검증 결과(PASS/FAIL), 판정된 실제 MIME 타입, 실패 사유 코드
선행 작업TM = SUCCESS
실행 조건master 파일 존재
성공 조건파일 존재 AND 용량 > 0 AND 확장자·MIME 허용 목록 포함 AND 파일 헤더 파싱 가능(비손상) AND checksum 일치
실패 조건위 조건 중 하나라도 불충족. 손상 파일·비허용 포맷은 재시도 불가 실패로 분류.
재시도 가능 여부제한적 — I/O 오류만 재시도, 검증 실패(손상·포맷 위반)는 즉시 FAILED 확정
재시도 정책I/O 오류 한정 최대 2회, 간격 1분
생성 파일/데이터없음 (판정 결과만 생성)
DB 저장 주요 값verify_result, detected_mime, fail_reason_code, verified_at
로그 기록 주요 값검증 항목별 결과(존재/용량/확장자/손상/checksum), 실패 사유 상세
관리자 화면 표시검증 결과, 항목별 통과 여부, 실패 사유(사용자 안내 문구 포함)
비고VERIFY 실패 시 콘텐츠 상태 → FAILED, 후속 작업은 모두 SKIPPED 처리.

3.3 MA / 미디어 정보 추출

작업 코드MA
작업 목적원본에서 기술 메타데이터를 추출하고 미디어 유형(VIDEO/IMAGE/AUDIO/DOC)을 확정하여 이후 분기를 결정한다.
입력 데이터master_path, VERIFY의 detected_mime
출력 데이터미디어 유형, 기술 메타데이터 JSON — 영상: 코덱·해상도·길이·프레임레이트·비트레이트·오디오 채널 / 이미지: 크기·포맷·EXIF·색상 정보 / 오디오: 길이·코덱·샘플레이트·채널
선행 작업VERIFY = SUCCESS
실행 조건분석 도구(ffprobe, ExifTool 등) 가용
성공 조건미디어 유형 확정 AND 유형별 필수 필드(영상: 코덱·해상도·길이) 추출 완료
실패 조건분석 도구 파싱 실패, 필수 필드 추출 불가, 유형 판별 불가
재시도 가능 여부가능 (읽기 전용, 멱등)
재시도 정책최대 3회, 간격 1분 → 5분 → 15분
생성 파일/데이터media_info JSON 레코드
DB 저장 주요 값media_type, media_info(JSON), duration, width, height, codec
로그 기록 주요 값사용 도구·버전, 추출 원본 출력(raw), 파싱 결과, 소요 시간
관리자 화면 표시미디어 유형, 주요 스펙(해상도·길이·코덱), 추출 실패 필드
비고media_type이 이후 TC/IMAGE_TC/AUDIO_TC/DOC_PREVIEW 분기의 유일한 기준값.

3.4 TC / 영상 트랜스코딩

작업 코드TC
작업 목적대용량 원본 영상(MOV/MXF/ProRes 등)을 웹 재생 가능한 저해상도 프록시(MP4/H.264 또는 HLS)로 변환한다.
입력 데이터master_path, media_info, 트랜스코딩 프로파일(해상도·비트레이트 프리셋)
출력 데이터Proxy Storage 내 프록시 영상 경로, 프록시 미디어 정보
선행 작업MA = SUCCESS AND media_type = VIDEO
실행 조건트랜스코딩 Worker 가용, Proxy Storage 쓰기 가능
성공 조건프록시 파일 생성 AND 재생 길이가 원본 대비 오차 ±1초 이내 AND 프록시 파일 자체 VERIFY 통과
실패 조건인코더 오류, 지원하지 않는 코덱, 출력 파일 손상, 타임아웃
재시도 가능 여부가능 (기존 출력 삭제 후 재실행)
재시도 정책최대 2회, 간격 5분 → 30분. 타임아웃 = max(30분, 원본 길이 × 3)
생성 파일/데이터Proxy Video (MP4/H.264 720p 기본, 정책에 따라 HLS 세그먼트)
DB 저장 주요 값proxy_path, proxy_codec, proxy_resolution, proxy_size, profile_id
로그 기록 주요 값사용 프로파일, ffmpeg 명령/버전, 진행률, 인코딩 속도, 오류 스트림
관리자 화면 표시진행률(%), 예상 남은 시간, 사용 프로파일, 실패 사유
비고다중 화질 정책 도입 시 프로파일별 하위 작업으로 분할 가능하도록 profile_id를 키에 포함.

3.5 IMAGE TC / 이미지 트랜스코딩

작업 코드IMAGE_TC
작업 목적TIFF/RAW/대용량 JPG 원본을 웹 표출용 이미지(JPG/PNG/WebP)로 변환한다.
입력 데이터master_path, media_info(크기·색공간·EXIF Orientation), 출력 프리셋(최대 변 길이·포맷·품질)
출력 데이터Proxy Storage 내 프록시 이미지 경로, 출력 크기
선행 작업MA = SUCCESS AND media_type = IMAGE
실행 조건이미지 처리 Worker 가용, Proxy Storage 쓰기 가능
성공 조건출력 파일 생성 AND 디코딩 가능 AND 지정 최대 변 길이 이내
실패 조건디코딩 실패(손상 RAW 등), 미지원 색공간, 메모리 초과
재시도 가능 여부가능
재시도 정책최대 3회, 간격 1분 → 5분 → 15분
생성 파일/데이터Proxy Image (기본 WebP, 최대 변 2048px)
DB 저장 주요 값proxy_path, proxy_format, proxy_width, proxy_height, proxy_size
로그 기록 주요 값입력/출력 포맷·크기, 색공간 변환 여부, EXIF Orientation 적용 여부
관리자 화면 표시작업 상태, 출력 포맷·크기, 실패 사유
비고EXIF Orientation은 픽셀에 적용 후 태그 제거. 개인정보성 EXIF(GPS)는 프록시에서 제거.

3.6 AUDIO TC / 오디오 트랜스코딩

작업 코드AUDIO_TC
작업 목적WAV/PCM 원본 오디오를 웹 미리듣기용 MP3/AAC로 변환한다.
입력 데이터master_path, media_info(길이·샘플레이트·채널), 출력 프리셋
출력 데이터Proxy Storage 내 프록시 오디오 경로
선행 작업MA = SUCCESS AND media_type = AUDIO
실행 조건인코딩 Worker 가용, Proxy Storage 쓰기 가능
성공 조건출력 파일 생성 AND 재생 길이 원본 대비 ±0.5초 이내
실패 조건인코더 오류, 미지원 코덱, 출력 손상
재시도 가능 여부가능
재시도 정책최대 3회, 간격 1분 → 5분 → 15분
생성 파일/데이터Proxy Audio (기본 AAC 128kbps). 선택 작업으로 Waveform PNG/JSON 생성 가능.
DB 저장 주요 값proxy_path, proxy_codec, proxy_bitrate, proxy_duration
로그 기록 주요 값입력/출력 코덱, 길이 비교값, 소요 시간
관리자 화면 표시작업 상태, 길이, 비트레이트, 실패 사유
비고WAVEFORM은 별도 선택 작업으로 분리(본 작업 실패와 독립).

3.7 CA / 썸네일·카탈로그 추출

작업 코드CA
작업 목적목록 화면용 대표 썸네일과 영상 구간별 카탈로그 이미지를 생성한다.
입력 데이터Proxy Video 또는 Proxy Image 경로, 추출 시점 정책(예: 대표 00:00:05, 카탈로그 00:00:10 / 00:00:20 …)
출력 데이터Thumbnail Storage 내 썸네일, Catalog Storage 내 카탈로그 이미지 목록(시점 매핑 포함)
선행 작업TC = SUCCESS (영상) 또는 IMAGE_TC = SUCCESS (이미지)
실행 조건프록시 파일 존재, 영상 길이 ≥ 최소 추출 시점(짧은 영상은 중간 프레임으로 대체)
성공 조건대표 썸네일 1건 생성 필수. 카탈로그는 정책 수량 중 1건 이상 생성.
실패 조건프레임 추출 실패, 출력 이미지 손상
재시도 가능 여부가능
재시도 정책최대 3회, 간격 1분 → 5분 → 15분
생성 파일/데이터Thumbnail(목록용, 예: 480px), Catalog Image N건(구간 미리보기용)
DB 저장 주요 값thumbnail_path, catalog_items(JSON: 시점 + 경로 배열)
로그 기록 주요 값추출 시점 목록, 성공/실패 건수, 대체 시점 사용 여부
관리자 화면 표시썸네일 미리보기, 카탈로그 생성 수량, 실패 사유
비고원본이 아닌 프록시에서 추출하여 Master Storage 접근을 차단한다.

3.8 DOC PREVIEW / 문서 미리보기 생성

작업 코드DOC_PREVIEW
작업 목적PDF/PPT/DOCX 등 문서를 웹에서 볼 수 있는 페이지별 이미지 또는 PDF 미리보기로 변환한다.
입력 데이터master_path, 문서 포맷, 변환 정책(페이지 수 상한·출력 해상도)
출력 데이터Proxy Storage 내 페이지 미리보기 이미지 목록(또는 변환 PDF), 총 페이지 수
선행 작업MA = SUCCESS AND media_type = DOC — VERIFY → MA에서 media_type 확정 후 DOCUMENT_INGEST 흐름으로 분기 (MA는 문서의 경우 기본 속성만 추출)
실행 조건문서 변환 엔진(LibreOffice/PDF 렌더러) 가용
성공 조건1페이지 이상 미리보기 생성 AND 총 페이지 수 확정
실패 조건암호화 문서, 변환 엔진 오류, 페이지 렌더링 실패
재시도 가능 여부가능 (암호화 문서는 재시도 불가 실패)
재시도 정책최대 2회, 간격 5분 → 30분
생성 파일/데이터Page Preview Image N건, 대표 썸네일(1페이지 기반)

로그 기록 주요 값변환 엔진·버전, 페이지별 성공 여부, 소요 시간

비고페이지 수 상한(예: 200p) 초과분은 SKIPPED 기록 후 상한까지만 생성.

실패 조건엔진 오류, 타임아웃

작업 코드TEXT_EXTRACT

3.11 INDEX / 검색 색인

작업 코드INDEX
작업 목적콘텐츠 제목·설명 메타데이터, 미디어 정보, OCR/추출 텍스트를 검색엔진에 색인한다.

실행 조건검색엔진 클러스터 가용

비고메타데이터 수정·선택 작업 완료 시 재색인 이벤트로 재실행된다.

3.12 PUBLISH / 서비스 가능 상태 전환

작업 코드PUBLISH
작업 목적유형별 필수 작업이 모두 SUCCESS인지 최종 확인하고 콘텐츠 상태를 READY로 전환하여 웹 표출을 허용한다.
입력 데이터content_id, 전체 작업 상태 목록, 유형별 필수 작업 매트릭스
출력 데이터콘텐츠 상태 READY, 게시 시각
선행 작업유형별 필수 작업 전체 = SUCCESS (§4 매트릭스 기준)
실행 조건필수 파생 파일(프록시·썸네일) 존재 재확인 통과
성공 조건상태 전환 트랜잭션 커밋 AND 웹 API에서 콘텐츠 조회 가능
실패 조건필수 작업 미완료/실패 존재, 파생 파일 누락, DB 트랜잭션 오류
재시도 가능 여부가능 (멱등)
재시도 정책최대 3회, 간격 1분. 필수 작업 실패가 원인이면 재시도하지 않고 FAILED 확정.
생성 파일/데이터없음 (상태 변경만)
DB 저장 주요 값content_status=READY, published_at, 검증 스냅샷(JSON)
로그 기록 주요 값필수 작업 체크리스트 결과, 상태 전환 전후 값
관리자 화면 표시게시 상태, 게시 시각, 미충족 항목 목록(실패 시)
비고READY 상태에서만 CMS 웹 화면에 표출. 원본 직접 표출은 어떤 상태에서도 금지.

3.13 CLEANUP / 임시 파일 정리

작업 코드CLEANUP
작업 목적Upload Temp Storage의 원본 사본과 처리 중 생성된 중간 산출물을 삭제하여 스토리지를 회수한다.
입력 데이터content_id, temp 경로, 중간 산출물 경로 목록
출력 데이터삭제 파일 목록, 회수 용량
선행 작업PUBLISH = SUCCESS 또는 콘텐츠 상태 = FAILED 확정 (유예 기간 경과 후)
실행 조건대상 파일이 다른 진행 중 작업에서 참조되지 않음
성공 조건대상 파일 전부 삭제 (이미 없는 파일은 성공 간주)
실패 조건권한 오류, 스토리지 I/O 오류
재시도 가능 여부가능 (멱등)
재시도 정책최대 5회, 간격 10분. 최종 실패 시 일배치 정리 대상으로 이관.
생성 파일/데이터없음 (삭제만)
DB 저장 주요 값cleaned_at, 회수 용량, 삭제 파일 수
로그 기록 주요 값삭제 경로 목록, 건별 결과, 회수 용량
관리자 화면 표시정리 상태, 회수 용량 (상세는 로그 링크)
비고Master Storage 파일은 절대 삭제 대상이 아니다. FAILED 콘텐츠의 temp 파일은 재처리 대비 72시간 유예 후 삭제.

5. 작업 의존 관계

  • TM → 콘텐츠 등록 완료 후 실행
  • VERIFY → TM = SUCCESS 이후 실행. 실패 시 후속 작업 전체 SKIPPED, 콘텐츠 FAILED.
  • MA → VERIFY = SUCCESS 이후 실행. media_type 확정으로 분기 결정.
  • TC / IMAGE_TC / AUDIO_TC → MA = SUCCESS 이후, 유형 일치 시 1개만 실행
  • DOC_PREVIEW, TEXT_EXTRACT → MA = SUCCESS(media_type=DOC 확정) 이후 병렬 실행 가능 (상호 독립)
  • CA → TC 또는 IMAGE_TC = SUCCESS 이후 (프록시 기반 추출). 문서는 DOC_PREVIEW 이후.
  • OCR → IMAGE_TC 또는 DOC_PREVIEW = SUCCESS 이후. 문서는 TEXT_EXTRACT 결과가 임계값 미만일 때.
  • INDEX → 유형별 필수 메타데이터·파생 파일 생성 완료 이후. 선택 작업은 대기하지 않음.
  • PUBLISH → 유형별 필수 작업 전체 = SUCCESS일 때만 실행
  • CLEANUP → PUBLISH = SUCCESS 또는 FAILED 확정 + 유예 기간 경과 후 실행

구현 기준: 의존 관계는 job_dependency 테이블(선행 job_id → 후행 job_id)로 표현하고, Worker는 선행 작업 상태가 모두 SUCCESS인 READY 작업만 큐에서 소비한다.

6. 재시도 정책

구분기본값비고
기본 재시도 횟수3회작업별 상세 정의(§3)가 우선
백오프지수 백오프 1분 → 5분 → 15분INDEX는 30초 시작, 최대 30분
재시도 불가 실패즉시 FAILED 확정손상 파일, 비허용 포맷, 암호화 문서, 필수 작업 미충족 PUBLISH

모든 작업은 멱등하게 구현한다 — 재실행 시 기존 출력물을 삭제/덮어쓰기하고 동일 결과를 보장한다.

7. 실패 처리 정책

  • 필수 작업 최종 실패 → 콘텐츠 상태 FAILED, 후속 필수 작업 SKIPPED, 관리자 알림 발송.
  • 선택 작업 최종 실패 → 콘텐츠 진행에 영향 없음. 작업 상태만 FAILED로 기록하고 대시보드에 노출.
  • VERIFY 실패 → 이후 작업 전체 실행 금지. 사용자에게 실패 사유(포맷/손상 등) 안내.
  • 부분 실패 (예: 카탈로그 5건 중 2건) → 필수 최소 조건 충족 시 SUCCESS + 경고 로그.
  • FAILED 콘텐츠 재처리 → 관리자 화면에서 실패 지점부터 재실행(성공한 선행 작업은 재실행하지 않음).
  • Master 파일 보존 → 어떤 실패 시나리오에서도 Master Storage의 원본은 삭제·변경하지 않는다.

8. 관리자 화면 표시 기준

화면표시 항목
워크플로우 대시보드상태별 작업 수(WAITING/READY/RUNNING/SUCCESS/FAILED/RETRY), 시간당 처리량, 평균 처리 시간, 실패율
콘텐츠 처리 상세작업 파이프라인 타임라인(작업별 상태·시작/종료 시각·소요 시간), 실패 사유, 재시도 버튼
작업 큐 모니터큐 대기 길이, Worker 가동 상태, 장기 RUNNING 작업(타임아웃 임박) 경고
실패 목록실패 작업 필터(유형·기간·사유 코드), 일괄 재시도, 로그 링크
공통 규칙모든 작업 행에 job_id, 작업 코드, 상태 뱃지, 시작/종료 시각, 소요 시간, 재시도 횟수 표시

9. DB 설계 시 고려사항

  • content (콘텐츠 상태: UPLOADING → REGISTERED → PROCESSING → READY / FAILED / ARCHIVED / DELETED) 와 job (작업 상태: WAITING / READY / RUNNING / SUCCESS / FAILED / RETRY / SKIPPED / CANCELED / TIMEOUT) 테이블 분리.
  • job 핵심 컬럼: job_id, content_id, job_type, status, retry_count, max_retry, started_at, finished_at, fail_reason_code, payload(JSON), result(JSON), worker_id.
  • 의존 관계는 job_dependency(job_id, depends_on_job_id)로 정규화 — 유형별 매트릭스는 워크플로우 템플릿 테이블에서 생성.
  • 파생 파일은 rendition 테이블로 관리: content_id, rendition_type(MASTER/PROXY_VIDEO/PROXY_IMAGE/PROXY_AUDIO/THUMBNAIL/CATALOG/PAGE_PREVIEW), storage_zone, path, size, checksum.
  • 상태 전이는 반드시 단방향 상태 기계로 검증(예: SUCCESS → RUNNING 전이 금지). 전이 이력은 job_history에 append-only 기록.
  • 워크플로우 정의 변경에 대비해 workflow_version을 콘텐츠에 스냅샷으로 저장.
  • 동시성: 작업 소비는 SELECT … FOR UPDATE SKIP LOCKED 또는 메시지 큐 ack 기반으로 중복 실행 방지.

CMS/MAM Workflow Admin OpenAPI Specification

워크플로우 관리자 OpenAPI 명세서 — OpenAPI 3.1 계약 문서 작성 기준

문서 버전 1.0 · 작성일 2026-07-04 · 상태: DRAFT · 선행 문서: Admin API Spec · Controller & Service Spec (각 v1.0)

1. 문서 목적

Admin API Spec v1.0을 기계 판독 가능한 OpenAPI 3.1 계약으로 정리하는 기준을 제공한다. 프론트엔드는 Swagger UI·Mock 서버로 연동하고, 백엔드는 Controller/FormRequest/Resource 구현 기준으로, QA는 테스트 케이스 원천으로 사용한다. 에러 응답·권한·상태 충돌(409) 응답을 스키마로 표준화한다. 본 문서의 YAML 발췌를 조합하면 openapi.yaml 전체를 구성할 수 있다.

2. OpenAPI 기본 정보

openapi: 3.1.0
info:
  title: Frame CMS/MAM Workflow Admin API
  version: 1.0.0
  description: >
    관리자 전용 워크플로우 운영 API. 모든 조작은 상태 기계 검증과
    감사 로그를 전제로 한다. 시각은 UTC ISO 8601.
servers:
  - url: /admin/workflows
security:
  - bearerAuth: []
  - adminSession: []

공통 응답 envelope: 성공 {success, data, meta?} / 실패 {success:false, error}. Content-Type은 application/json 고정.

14. Permission 문서화

모든 path에 벤더 확장 x-permission을 선언한다 — Swagger UI 플러그인이 뱃지로 표시하고, 계약 테스트가 라우트 미들웨어와 대조한다.

/jobs/{id}/release-lock:
  post:
    x-permission: workflow.release_lock
    x-risk: HIGH          # LOW | MED | HIGH — UI 이중 확인 기준

권한 체계: view / logs.view / retry / cancel / reprocess / release_lock / worker.manage / force_publish — Admin API Spec §3과 동일. HIGH는 x-risk: HIGH로 병기.

15. available_actions 문서화

available_actions는 서버가 현재 상태 × 호출자 권한으로 계산한 실행 가능 액션 배열이다. 프론트는 이 배열만으로 버튼 노출을 결정하고 자체 판정 로직을 두지 않는다.

ContentAction: { type: string, enum: [view_detail, reprocess, cancel, view_logs, publish_retry] }
JobAction:     { type: string, enum: [view_logs, retry, cancel, release_lock, update_priority, view_content] }
WorkerAction:  { type: string, enum: [disable, enable, clear_error, view_current_job, view_logs] }

16. Pagination / Sorting / Filtering

  • page(기본 1) · per_page(기본 50, 최대 200) — 초과 시 200으로 절삭.
  • sort: 콤마 구분 + - 내림차순 (sort=-priority,created_at) — path별 화이트리스트를 parameter description에 명시, 목록 외 필드는 무시.
  • 다중 status: status=FAILED,TIMEOUT (콤마 구분 — style: form, explode: false).
  • date_from/date_to: ISO 8601, 반개구간 [from, to).
  • keyword: 제목/파일명/uuid 부분 일치.
  • 공통 파라미터는 components.parameters로 정의해 재사용(PageParam, PerPageParam, SortParam).

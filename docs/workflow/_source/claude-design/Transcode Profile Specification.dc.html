CMS/MAM Transcode Profile & Rendition Preset Specification

트랜스코딩 프로파일·렌디션 프리셋 정의서 — Worker 출력 규격 표준

문서 버전 1.0 · 작성일 2026-07-04 · 상태: DRAFT · 선행 문서: Worker Agent Spec · Migration & Seed Spec (각 v1.0)

1. 문서 목적

Master 원본을 웹 표출용 Proxy·Thumbnail·Catalog·Preview로 변환하는 표준 프리셋을 확정한다: 유형별 출력 규격, transcode_profiles seed 기준, ffmpeg·libvips·LibreOffice 실행 옵션, 그리고 media_renditions의 profile_id/variant_key/rendition_type 연결 규칙을 정의한다. Worker Handler는 본 문서의 프로파일만 참조하며 출력 규격을 코드에 하드코딩하지 않는다.

2. 프로파일 설계 원칙

  • Master 파일은 절대 수정·삭제하지 않는다 — 모든 변환은 읽기 전용 입력.
  • 웹 표출은 프록시·미리보기 파일만 사용한다.
  • 기본 목표는 저해상도·저용량·빠른 웹 재생 — 품질 보존이 아니라 미리보기·운영 편의가 목적.
  • 프리셋은 transcode_profiles seed로 관리 — 코드 하드코딩 금지, 운영 중 조정 가능.
  • 다중 화질 확장 대비 variant_key 사용 (§10).
  • 모든 출력은 임시 경로 생성 → 검증(§16) → atomic rename.

10. variant_key 정책

표준 값: default · 720p · 480p · 360p · hls_720p · thumb_480 · thumb_240 · catalog_default · page_preview · wave_json · wave_png · ocr_default. 규칙: 소문자 snake, profile code와 1:1 대응(profile이 variant_key를 소유).

unique key 재구성 (Migration Spec §7의 partial unique 3종을 variant_key 포함으로 대체):

-- 단건: content_id + rendition_type + variant_key
CREATE UNIQUE INDEX uq_rend_single ON media_renditions
  (content_id, rendition_type, variant_key)
  WHERE page_no IS NULL AND timecode_ms IS NULL;
-- 페이지: … + page_no        (WHERE page_no IS NOT NULL)
-- 타임코드: … + timecode_ms  (WHERE timecode_ms IS NOT NULL)

variant_key는 NOT NULL DEFAULT 'default'로 추가 — 기존 행 마이그레이션 불필요, 다중 화질 도입 시 스키마 변경 없이 720p/480p 행이 공존한다.

11. ffmpeg 옵션 표준

  • 공통: -y -hide_banner -loglevel error -progress pipe:1 — 진행률은 pipe 파싱, stderr는 오류 전용.
  • 스케일: -vf "scale='min(1280,iw)':-2" — 업스케일 금지, 짝수 높이 보장(-2).
  • fps: -r 30은 원본 > 30fps일 때만 적용(params 플래그).
  • 레이트 제어: CRF 23 + -maxrate/-bufsize로 상한 — 화질·용량 균형.
  • -movflags +faststart 필수 — 웹 프로그레시브 재생.
  • -pix_fmt yuv420p 필수 — 브라우저 호환(4:2:2/4:4:4 원본 대응).
  • exit ≠ 0 또는 출력 duration 검증 실패 → 임시 파일 삭제 + EXTERNAL_TOOL_ERROR.
ffmpeg -y -hide_banner -loglevel error -progress pipe:1 \
  -i {master} \
  -vf "scale='min(1280,iw)':-2" -c:v libx264 -preset medium -crf 23 \
  -maxrate 2500k -bufsize 5000k -pix_fmt yuv420p \
  -c:a aac -b:a 128k -ac 2 \
  -movflags +faststart {out}.tmp.mp4
# GPU 노드: -c:v h264_nvenc -preset p4 -cq 26 (profile params.gpu_codec로 전환)

12. 이미지 처리 옵션 표준 (libvips)

  • autorotate(EXIF Orientation 픽셀 적용) 후 메타데이터 strip — GPS·기기 정보 제거.
  • 리사이즈는 최대 변 기준 축소만(업스케일 금지) — vipsthumbnail --size WxH.
  • quality: WebP 82(프록시)/75(썸네일), JPEG 85.
  • 색공간: CMYK·AdobeRGB → sRGB 변환(--eprofile srgb), ICC 프로파일 제거.
  • 대형 이미지: vips 스트리밍 처리 + 픽셀 수 상한(예: 10만×10만 거부 — PERMANENT).
  • 디코딩 실패 → USER_FILE_ERROR / 도구 크래시 → EXTERNAL_TOOL_ERROR.

13. 문서 변환 옵션 표준

  • Office → PDF: soffice --headless --norestore --convert-to pdf --outdir {tmp} — job마다 전용 프로필 디렉터리(-env:UserInstallation)로 프로세스 격리, 완료 후 프로세스 그룹 종료.
  • PDF → 이미지: pdftoppm -r 144 -png -f 1 -l {limit} {pdf} {prefix} → vips로 WebP 변환·리사이즈.
  • page limit 200 — 초과분은 생성하지 않고 WARN 로그(SUCCESS 유지).
  • timeout: 문서당 30분(job timeout과 별개로 페이지당 10초 가드).
  • 암호화 문서: pdfinfo 사전 검사에서 감지 → ENCRYPTED_DOC (PERMANENT).
  • 개별 페이지 렌더 실패: 해당 페이지 건너뛰고 기록 — 1페이지 이상 성공이면 job SUCCESS.

15. Worker 적용 방식

  1. workflow_template_steps.config에 profile_code 저장 (예: TC step → {"profile":"VIDEO_PROXY_720P"}).
  2. 인스턴스화 시 config가 job.payload로 복사 — 실행 시점 프로파일 고정(재현성).
  3. Handler가 code로 transcode_profiles 조회 → is_active=false면 실행 거부(SYSTEM_ERROR, 재시도 안 함 — 운영 설정 오류로 알림).
  4. params를 도구 인자로 변환(ProfileCompiler — 프로파일→인자 배열 매핑 단일 클래스).
  5. 생성 rendition에 profile_id + variant_key 기록.
  6. GPU Worker는 params.gpu_codec 존재 + 자체 gpu.enabled일 때만 GPU 경로 사용.

17. 운영 시 고려사항

  • 프로파일 변경: 기존 산출물은 자동 재처리하지 않는다 — 변경 후 신규 콘텐츠만 적용, 소급은 관리자 일괄 재처리로. rendition의 profile_id로 세대 식별 가능.
  • 버전 관리: 프로파일은 UPDATE 대신 새 code 추가(VIDEO_PROXY_720P_V2) + 구버전 비활성 — 재현성 보존.
  • 다중 화질: variant_key unique 재구성(§10) 선행 후 480P 등 활성화 — TC job을 프로파일별로 분할할지(권장) 단일 job 다중 출력일지는 그때 결정.
  • HLS 도입 시: 세그먼트 다건을 rendition 1행(playlist path) + metadata(세그먼트 목록)로 저장 — 행 폭발 방지.
  • 폐쇄망: ffmpeg/libvips/LibreOffice/Tesseract 버전을 이미지에 고정(버전 업은 검증 후 일괄) — 버전 차이가 출력 결과·검증 기준에 영향.
  • GPU 인코딩은 CRF와 화질 특성이 다름(cq 26 ≈ crf 23 근사) — 노드별 화질 편차를 수용할지 CPU 통일할지 운영 결정 필요.

문서 버전 1.0 · 작성일 2026-07-04 · 상태: DRAFT · 선행 문서: Queue & Worker Spec · State Machine Spec · Migration & Seed Spec (각 v1.0)

1. 문서 목적

본 문서는 개발자가 실제 Worker 프로세스와 13개 Job Handler를 구현할 수 있도록 공통 실행 루프·Job Claim·Heartbeat/Lock 연장·진행률 기록·실패 처리·외부 도구 호출·산출물 저장 방식을 코드 수준으로 정의한다. Worker는 Laravel artisan 커맨드로 실행되는 장기 실행 PHP CLI 프로세스이며, supervisor가 관리한다.

4. Worker 프로세스 부팅 흐름

  1. 설정 파일 로드 (§17) — worker_name·worker_type·supported_job_types 확인, 누락 시 즉시 종료(exit 1).
  2. 외부 도구 점검 — 지원 job_type에 필요한 바이너리 실행 확인: ffmpeg -version, ffprobe -version, vips --version, soffice --version, tesseract --version, 검색엔진 ping. 하나라도 실패 시 status=ERROR로 등록 후 종료.
  3. Storage 접근 점검 — 각 zone 마운트 존재 + 쓰기 zone에 테스트 파일 write/delete.
  4. PostgreSQL 연결 확인.
  5. workflow_worker_agents upsert (worker_name 기준 — hostname·ip·capacity·version 갱신).
  6. status = ONLINE 전환 (WorkerStateMachine 경유).
  7. heartbeat 루프 시작 (별도 타이머, 30초).
  8. SIGTERM/SIGINT 핸들러 등록 (§14) → Job Claim 루프 진입 (§5).

5. 공통 Worker 실행 루프

// app/Console/Commands/WorkflowWorkerCommand.php → AbstractWorker::run()
public function run(): int {
  pcntl_async_signals(true);
  pcntl_signal(SIGTERM, fn() => $this->shuttingDown = true);
  pcntl_signal(SIGINT,  fn() => $this->shuttingDown = true);

  while (! $this->shuttingDown) {
    $me = $this->agents->refresh($this->workerId);          // 자신의 상태 재조회
    if (in_array($me->status, [WorkerStatus::Disabled, WorkerStatus::Error])) {
      $this->sleepWithJitter(); continue;                    // Claim 중단, 프로세스는 유지
    }

    $job = $this->claim->tryClaim($this->workerId, $this->supportedTypes);
    if ($job === null) { $this->sleepWithJitter(); continue; }  // 2~5s + jitter

    $this->locks->startHeartbeat($job->id, $this->workerId);    // 30s 타이머
    try {
      $result = $this->executeJob($job);                        // Handler 위임 (§8)
      $result->success
        ? $this->finalizeSuccess($job, $result)                 // SUCCESS + renditions
        : $this->finalizeFailure($job, $result);                // RetryPolicy → RETRY/FAILED
    } catch (LeaseLostException $e) {
      $this->logs->warn($job, 'lease lost — result discarded'); // 결과 폐기 (§7)
    } catch (Throwable $e) {
      $this->finalizeFailure($job, JobResult::systemError($e));
    } finally {
      $this->locks->stopHeartbeat();
      $this->locks->release($job->id, $this->workerId);         // lock DELETE (자기 소유만)
      $this->agents->clearCurrentJob($this->workerId);          // current_job_id=null, BUSY→ONLINE
    }
  }
  $this->agents->markOffline($this->workerId);                  // graceful shutdown (§14)
  return 0;
}

6. Job Claim 구현 (JobClaimService)

public function tryClaim(int $workerId, array $types): ?WorkflowJob {
  // Claim은 최상위 트랜잭션 소유자 — 내부의 상태 전이·history는 이 트랜잭션에 참여
  return DB::transaction(function () use ($workerId, $types) {
    $row = DB::selectOne(
      "SELECT id, status FROM workflow_jobs
       WHERE status IN ('READY','RETRY')
         AND (next_attempt_at IS NULL OR next_attempt_at <= now())
         AND job_type = ANY(?)
       ORDER BY priority DESC, created_at ASC
       LIMIT 1 FOR UPDATE SKIP LOCKED", ['{'.implode(',', $types).'}']);
    if (! $row) return null;

    DB::insert("INSERT INTO workflow_job_locks
      (job_id, locked_by_worker_id, locked_until, heartbeat_at)
      VALUES (?, ?, now() + interval '600 seconds', now())", [$row->id, $workerId]);

    DB::update("UPDATE workflow_jobs SET status='RUNNING', worker_id=?,
        started_at=now(),
        retry_count = retry_count + CASE WHEN status='RETRY' THEN 1 ELSE 0 END,
        updated_at=now()
      WHERE id=?", [$workerId, $row->id]);

    DB::insert("INSERT INTO workflow_job_histories (job_id, from_status, to_status, actor, note)
      VALUES (?, ?, 'RUNNING', ?, 'claimed')", [$row->id, $row->status, "worker:$workerId"]);

    DB::update("UPDATE workflow_worker_agents SET current_job_id=?, status='BUSY',
      updated_at=now() WHERE id=?", [$row->id, $workerId]);

    return WorkflowJob::findOrFail($row->id);
  });
}

retry_count는 RETRY→RUNNING 재진입 시에만 증가(CASE). locks PK가 이중 lease를 DB 레벨에서 차단 — INSERT 충돌 시 트랜잭션 롤백 후 null 반환(정상 흐름).

7. Heartbeat / Lock 연장 (JobLockService)

// 30초마다 (pcntl_alarm 또는 이벤트 루프 타이머)
$rows = DB::update("UPDATE workflow_job_locks
  SET heartbeat_at=now(), locked_until=now() + interval '600 seconds'
  WHERE job_id=? AND locked_by_worker_id=?", [$jobId, $workerId]);
DB::update("UPDATE workflow_worker_agents SET last_heartbeat_at=now() WHERE id=?", [$workerId]);

if ($rows === 0) $this->consecutiveFailures++;   // lease 상실 or lock 회수됨
else             $this->consecutiveFailures = 0;
if ($this->consecutiveFailures >= 2) throw new LeaseLostException($jobId);
  • 0 rows = lease 상실 — Scheduler가 회수했거나 DB 단절. 2회 연속이면 실행 중단: 외부 프로세스 kill, 결과 저장 금지, WARN 로그.
  • 이후 모든 결과 기록(SUCCESS UPDATE, rendition upsert)은 WHERE status='RUNNING' AND worker_id=:me CAS — 0행이면 폐기(fencing).

8. Job Handler 인터페이스

interface WorkflowJobHandler {
  public function supports(string $jobType): bool;
  public function handle(WorkflowJob $job, JobExecutionContext $ctx): JobResult;
  public function cancel(WorkflowJob $job): void;   // 외부 프로세스 kill + 부분 산출물 정리
}

final class JobExecutionContext {
  public WorkflowJob $job;
  public Content $content;
  public ?MediaFile $mediaFile;
  public array $payload;                 // job.payload
  public WorkflowWorkerAgent $worker;
  public MediaStorageService $storage;   // zone별 경로 해석
  public JobLogService $logger;          // attempt 스코프 로거
  public JobProgressService $progress;   // report(percent, message, etaSec)
  public CancellationToken $cancelToken; // cancel_requested_at 폴링 + shutdown 플래그
}

final class JobResult {
  public bool $success;
  public array $resultData;              // job.result에 저장
  public array $renditions;              // RenditionService가 upsert할 스펙 목록
  public ?string $failReasonCode;
  public ?string $failMessage;
  public ?FailureType $failureType;      // §13 enum
  public bool $retryable;
  public array $logs;                    // 추가 기록할 로그 항목
}

10. 외부 도구 호출 정책

  • Laravel Process 파사드(Symfony Process 기반) 사용 — 쉘 문자열 금지, 인자 배열만(command injection 원천 차단). 파일 경로는 storage 서비스가 해석한 절대 경로만 전달.
  • timeout = job.timeout_sec − 30s(정리 여유). 초과 시 프로세스 kill + EXTERNAL_TOOL_ERROR.
  • stdout/stderr 스트리밍 capture — 각 64KB 링버퍼 유지(진행률 파싱용은 라인 콜백). 전체 로그는 임시 파일로 받고 §16 정책으로 저장.
  • exit code ≠ 0 → stderr 마지막 20줄을 fail_message로. 도구별 알려진 코드는 fail_reason_code 매핑 테이블 관리.
  • cancel: CancellationToken 신호 시 SIGTERM → 5초 대기 → SIGKILL. LibreOffice는 프로세스 그룹 단위 kill.
  • 임시 파일: {zone}/.tmp/{job_id}/ 아래에만 생성 — job 종료 시(성공/실패 무관) 디렉터리 삭제.

11. 진행률 업데이트 (JobProgressService)

  estimated_remaining_sec, updated_at)

  • 종결 시 Worker가 행 DELETE(§9 CLEANUP이 누락분 보강) — 100% 유지 대신 삭제를 표준으로 한다(RUNNING 화면 전용 데이터).

14. 취소 / Graceful Shutdown

  • SIGTERM: shuttingDown=true → 신규 Claim 중단 → 현재 job 완료 대기(기본, drain). supervisor stopwaitsecs는 최장 job 고려(TRANSCODE 7500s).
  • 즉시 종료 필요 시(2번째 SIGTERM): 현재 Handler의 cancel() 호출 — 외부 프로세스 kill → 부분 산출물(.tmp) 삭제 → job은 정리하지 않고 종료 → lease 만료로 Scheduler가 RETRY 회수.
  • 관리자 취소: CancellationToken이 heartbeat 주기마다 cancel_requested_at 확인 → 감지 시 cancel() → RUNNING→CANCELED 전이(StateMachine) + lock 해제 + history(actor=admin 요청 참조).
  • 종료 직전 agents.status=OFFLINE + current_job_id 정리.

15. 안전한 파일 처리 정책 (MediaStorageService)

  • 모든 쓰기는 {zone}/.tmp/{job_id}/에 먼저 → 완료 검증(크기>0, checksum, 포맷 probe) → 최종 경로로 atomic rename(동일 파일시스템 보장).
  • 동일 path 덮어쓰기 = 재실행 upsert 케이스만 허용 — rename이 원자적이므로 부분 쓰기 노출 없음.
  • 실패·취소 시 .tmp 디렉터리 전체 삭제.
  • MASTER zone 보호: 서비스에 assertNotMasterMutation(path) 가드 — MASTER 경로에 대한 수정·삭제 API 자체를 제공하지 않는다(TM의 최초 쓰기만 예외 메서드).
  • 웹 표출 파일(PROXY/THUMBNAIL/CATALOG/DOCUMENT)만 갱신 가능.

16. 로그 기록 정책 (JobLogService)

  • attempt 시작 시 INFO(command 포함), 종료 시 INFO/ERROR(message + detail JSON) — 최소 2건.
  • stdout/stderr는 각 1MB 상한으로 컬럼 저장(head 256KB + tail 768KB 절단 표기). 초과 원본은 {zone}/.logs/{job_id}/attempt{n}.log로 파일 보관, detail에 경로 기록.
  • fail_reason_code ↔ 사용자 안내 문구 매핑은 단일 PHP 상수 맵(FailReasonCatalog)으로 관리 — API·화면·알림이 공유.
  • level: DEBUG(개발 시), INFO(정상 절차), WARN(부분 실패·lease 경고), ERROR(실패 확정).

동시성 모델(확정): 초기 구현은 Worker 프로세스 1개 = Job 1개. 동시성은 프로세스 내부 멀티스레드가 아니라 supervisor numprocs로 해결한다. current_job_id는 이 전제에서만 유효하며, max_concurrency는 노드 용량 표시/향후 확장용으로만 사용(Claim 로직이 참조하지 않음). 추후 1 Worker N Job이 필요하면 workflow_worker_agent_slots 테이블을 별도 검토한다. heartbeat는 별도 커맨드가 아니라 Worker 프로세스 내부 타이머로 처리(프로세스 분리 시 lease 의미가 깨짐). supervisor 프로그램 단위 = Worker 1 프로세스, numprocs로 동시 실행 수 제어.

20. 운영 시 고려사항

  • PHP 장기 실행 대비: 메모리 누수 감시 — job N건(예: 100건) 처리 후 자발적 재시작(supervisor autorestart).
  • DB 커넥션 단절 시 지수 백오프 재연결 — heartbeat 실패 카운트와 연동.
  • Worker 버전 롤링 배포: DISABLED(drain) → 배포 → enable. 배포 중 큐 적체 감시.
  • 시계 동기화(NTP) 필수 — lease·timeout 판정이 시각 기반.
